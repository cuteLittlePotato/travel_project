## 一、项目功能全景

云游坊是一个 AI 驱动的旅游推荐与规划平台，包含**六个功能域**：

| 功能域 | 面向 | 职责概述 |
|--------|------|---------|
| **用户与账户** | C 端 | 注册登录、个人资料、偏好与隐私设置 |
| **景点内容服务** | C 端 | 景点浏览、搜索、详情、发现、推荐 |
| **智能对话** | C 端 | AI 对话交互前台 |
| **旅游计划** | C 端 | 行程生成、编辑、状态流转 |
| **足迹** | C 端 | 旅行记录与 UGC |
| **平台运营** | B 端 | 基础数据、知识资产、模型、用户、系统管理 |

其中 **Agent 引擎**与**记忆服务**是支撑智能对话的底层能力，**知识库**与**知识图谱**是支撑检索的知识资产，**模型管理**与**额度服务**是支撑 AI 调用的基础设施。

## 二、模块划分

### 2.1 模块总览

共划分 **17 个模块**，按层分为四组：

```
┌─────────────────────────────────────────────────────────────┐
│  接入层（用户直接交互）                                        │
│  M01 用户与账户    M02 景点内容    M03 对话交互                │
│  M04 旅游计划      M05 足迹                                      │
├─────────────────────────────────────────────────────────────┤
│  能力层（支撑业务逻辑）                                        │
│  M06 Agent 引擎    M07 记忆服务    M08 检索调度                │
│  M17 推荐引擎                                                  │
├─────────────────────────────────────────────────────────────┤
│  知识层（数据资产）                                            │
│  M09 知识库        M10 知识图谱                                │
├─────────────────────────────────────────────────────────────┤
│  基础层（平台能力）                                            │
│  M11 基础数据    M12 模型管理    M13 额度服务                  │
│  M14 用户运营    M15 系统管理    M16 数据看板                  │
└─────────────────────────────────────────────────────────────┘
```

> 说明：M17 推荐引擎归入**能力层**。理由是它本质是一项「能力」（计算与决策），而非「基础数据」；且它依赖 M07 记忆服务与 M12 模型管理，若置于基础层会违反「同层模块不直接依赖」原则。

### 2.2 各模块职责

#### M01 用户与账户

**职责**：C 端用户的身份认证、资料维护与账户设置。

| 能力 | 说明 |
|------|------|
| 注册登录 | 手机号、邮箱、第三方（微信/支付宝/微博）；多方式可绑定同一账户 |
| 个人资料 | 昵称、头像、性别、地区 |
| 偏好设置 | 旅游偏好（类型/风格/预算），用户可手动查看与调整 |
| 账户安全 | 修改密码、账号绑定管理 |
| 隐私设置 | 资料可见性、足迹可见性、计划可见性、个性化推荐开关、通知开关 |
| 额度查看 | 展示当日模型调用额度（次数 / token 双维） |
| 注销 | 注销后清除账号与关联数据 |

**边界**：
- 不负责记忆的生成与学习（属 M07）
- 不负责额度的计量与判定（属 M13），仅做展示

---

#### M02 景点内容

**职责**：C 端景点内容的浏览、搜索与展示。

| 能力 | 说明 |
|------|------|
| 首页 | 热度排行（含热度值与推荐理由悬停） |
| 分类浏览 | 按类型（历史人文/自然景色等）、按省份-城市两级联动 |
| 搜索 | 按景点名称、城市、关键词 |
| 景点详情 | 基础信息、图片、简介、门票、开放时间、建议时长、最佳季节、交通指南 |
| 关联内容展示 | 历史人物卡片、事件时间线、文化标签、附近景点、相似景点 |
| 知识图谱入口 | 详情页跳转至景点知识图谱可视化页 |
| 快捷操作 | 加入计划、标记足迹、咨询助手 |

**边界**：
- 关联内容的**数据**来自 M10 知识图谱，本模块只负责展示
- 详情页展示哪些关联内容由 M08 检索调度决定

---

#### M03 对话交互

**职责**：用户与 AI 的对话前台，负责消息收发与呈现。

| 能力 | 说明 |
|------|------|
| 消息收发 | 文本输入、流式接收（SSE）、Markdown 渲染 |
| 会话管理 | 新建会话、切换历史会话、删除会话、清空当前会话 |
| 上下文承载 | 展示当前会话的完整消息记录 |
| 模型切换 | 显示当前所用文本模型，可手动切换（仅本会话内生效） |
| 快捷提问 | 预置常见问题按钮 |
| 额度展示 | 对话界面呈现当日剩余额度 |
| 意图澄清 | 意图不明确时以选项形式让用户确认 |
| 方案卡片渲染 | 展示行程方案对比卡片与详情 |
| 方案编辑入口 | 提供对话式调整与可视化编辑双入口 |
| 中断等待 | 缺少关键信息时展示追问表单或追问消息 |

**边界**：
- 不负责意图识别（属 M06）
- 不负责方案生成（属 M04）
- 不直接调用模型与检索（属 M06 编排）

---

#### M04 旅游计划

**职责**：行程方案的全生命周期管理。

| 能力 | 说明 |
|------|------|
| 方案生成 | 接收需求参数，生成 2-3 个差异化方案（按预算分层） |
| 方案对比 | 按总预算 → 景点质量 → 住宿 → 交通 → 餐饮 的优先级呈现 |
| 方案详情 | 逐日景点、时段、门票、交通、用餐、住宿、预算明细、时间轴、文化背景、游玩建议、备选方案 |
| 需求收集 | 必要信息（目的地/天数/预算）缺失时追问；可选信息缺失时按 记忆 → 默认值 降级 |
| 方案调整 | 景点/住宿/餐饮/交通/整体五个维度的增删改 |
| 约束冲突处理 | 时间冲突、预算超支、逻辑冲突时主动提示并给出建议 |
| 保存策略 | 调整后询问「保存为新方案」或「覆盖原方案」 |
| 状态流转 | 规划中 → 待进行 → 进行中 → 已完成 |
| 计划列表 | 按状态分类、搜索、筛选、排序 |
| 手动编辑 | 同行人数、逐日行程时间轴（时段+活动类型+描述） |
| 行程与会话解耦 | 行程为独立资源，任何会话均可查询与编辑 |

**边界**：
- 不负责「如何生成」（由 M06 编排调用 M08 检索 + 模型推理）
- 不负责状态流转的自动触发判断（由定时任务触发状态变更，属计划模块内部规则）

---

#### M05 足迹

**职责**：用户的旅行记录与内容沉淀。

| 能力 | 说明 |
|------|------|
| 自动生成 | 计划标记完成时，自动按行程生成足迹 |
| 手动添加 | 补录平台外去过的景点 |
| UGC | 照片、游记、评分 |
| 统计展示 | 去过的景点数、走过的省份数、城市数、照片数 |
| 列表展示 | 足迹卡片（景点、日期、评分、游记摘要、来源标识） |

**边界**：
- 不负责把足迹数据用于推荐（由 M07 采集、M17 使用）

---

#### M06 Agent 引擎

**职责**：AI 对话的决策与编排中枢。这是系统的核心能力模块。

| 能力 | 说明 |
|------|------|
| 意图识别 | 识别为行程规划 / 景点咨询 / 知识探索 / 预订咨询 / 交通咨询 / 天气咨询 |
| 置信度处理 | >80% 直接执行；70-80% 确认；<70% 反问澄清 |
| 混合意图处理 | 拆解为多轮对话逐个处理 |
| 路由分发 | 行程规划走 6 节点状态机；其他意图走 Plan + ReAct |
| 行程规划编排 | 信息收集 → 检索候选景点 → 生成方案 → 展示 → 处理调整 → 执行调整 |
| Plan 阶段 | 为简单意图制定执行步骤计划 |
| ReAct 循环 | Think → Act → Observe 循环，LLM 判断信息足够或达 10 次上限则终止 |
| 工具编排 | 统一调度 12 类工具（数据库查询、RAG、GraphRAG、地图、天气、预订、路线、预算、联网搜索、行程生成、记忆查询、结束） |
| 工具容错 | 超时重试 3 次后降级；空结果先优化查询再换工具最后 LLM 兜底 |
| 上下文管理 | 达模型上限 70% 时压缩：历史摘要 + 最新 N 轮完整对话 |
| 会话状态管理 | 每轮保存消息链、意图、流程状态、工作记忆、ReAct 状态；支持无缝恢复 |
| 模型不可用处理 | 不自动降级，明确报错并提示用户可选模型 |
| 来源标注 | 回答默认不显示来源，用户可点击查看引用详情 |

**边界**：
- 检索的**执行**委托 M08（本模块只决定「调什么、调几次」）
- 会话状态的**存储**由本模块定义结构，实际持久化在会话存储中
- 行程方案的**业务规则**（差异化维度、约束冲突处理）属 M04，本模块负责触发

---

#### M07 记忆服务

**职责**：用户偏好的学习、存储与供给。

| 能力 | 说明 |
|------|------|
| 短期记忆 | 会话内的上下文（消息链、摘要） |
| 长期记忆 | 跨会话保存用户偏好、历史行为、情境信息 |
| 工作记忆 | 行程规划流程的中间状态（候选景点、已生成方案、调整历史） |
| 偏好学习 | 从对话、足迹、计划、评分中提取偏好 |
| 权重衰减 | 最近的偏好权重更高，旧偏好逐渐降权 |
| 记忆读取 | 会话开始时全量加载长期记忆；可选信息缺失时作为降级依据 |
| 用户可见性 | 用户可查看记忆内容，不可直接编辑 |
| 数据清理 | 账号注销时立即删除 |

**边界**：
- 不负责记忆的**呈现**（属 M01 个人中心）
- 不负责基于记忆的**推荐决策**（属 M17）

---

#### M08 检索调度

**职责**：统一调度多种检索源，融合结果后交给 Agent。

| 能力 | 说明 |
|------|------|
| 检索策略路由 | 按问题类型选择检索组合（事实查询/描述性/关联推理/多跳推理） |
| 并行检索 | 同时调用数据库、RAG、GraphRAG |
| 结果融合 | 按优先级合并且去重 |
| 冲突处理 | 结果矛盾时选最权威来源（官方数据 > 知识库 > 通用知识） |
| 降级兜底 | RAG 为空用通用知识；GraphRAG 为空查间接关系 |
| 来源追溯 | 记录每个结论的来源，供 M03 展示引用 |

**边界**：
- 检索的**具体实现**委托给数据提供方：数据库查询→M11、RAG→M09、GraphRAG→M10
- 本模块只负责「选哪种、怎么合、如何兜底」

---

#### M09 知识库

**职责**：RAG 知识库的建设与维护（B 端）。

| 能力 | 说明 |
|------|------|
| 知识库创建 | 管理员自主创建，命名、描述、容量、权限 |
| 知识库配置 | 切分参数（Chunk 大小、重叠、分隔符）、向量化模型、重排序模型 |
| 分隔符管理 | 内置 6 种（空行/换行/句号/问号/感叹号/分号）+ 自定义，多选 + 优先级排序 |
| 文件上传 | 批量上传；支持 PDF/Word/Excel/TXT/Markdown/图片/网页链接；单文件 ≤50MB |
| 文件归一化 | 格式路由 → 解析归一化 → 清洗去噪 → 结构感知切分 → 向量化 |
| 处理状态机 | 排队中 → 解析中 → 切分中 → 向量化中 → 完成/失败 |
| 解析预览 | 三标签页：原始文档 / 转换后 Markdown / 切片预览（含标题路径） |
| 文档管理 | 查看、重新索引、重试、取消、删除 |
| 配置变更规则 | 切分参数仅影响新文件；向量化模型变更需整库重建（暂停检索） |
| 文件更新 | 同名覆盖；冲突时按时间优先并标注来源 |
| 统计监控 | 文档数、容量、向量数、检索性能 |

**边界**：
- 不负责向量化模型的**注册**（属 M12），只负责选用
- 不负责检索结果的**融合**（属 M08）

---

#### M10 知识图谱

**职责**：景点关联知识的建设、维护与应用（B 端建设，C 端消费）。

| 能力 | 说明 |
|------|------|
| 实体管理 | 历史人物、历史事件、文化元素的 CRUD；景点实体来自 M11 |
| 关系管理 | 关系类型配置、关系创建编辑、关系属性填写 |
| 关系查询可视化 | 以景点为中心查看关系网络、筛选关系类型、导出 |
| 批量导入 | 实体与关系的 CSV/Excel 批量导入、校验去重 |
| 图谱统计 | 实体数与关系数（按类型）、覆盖景点数、孤立节点检测 |
| C 端图谱浏览 | 可交互的关系网络图，节点可点击展开详情、可跳转至其他实体的图谱 |

**边界**：
- 图谱的**数据**被 M02 展示、M08 检索、M06 使用
- 不负责 GraphRAG 的查询逻辑（属 M08）

---

#### M11 基础数据

**职责**：平台结构化基础数据的维护（B 端）。

| 能力 | 说明 |
|------|------|
| 省市管理 | 省份-城市两级管理，含简介、热门度、封面图 |
| 景点管理 | CRUD、批量导入导出；含地理坐标、分类标签、热度权重、上架状态 |
| 餐饮管理 | CRUD；含位置、类型、人均、营业时间、特色菜 |
| 酒店管理 | CRUD；含位置、星级、价格区间、房型、设施 |
| 景区交通管理 | 仅维护景区专属交通（观光车、索道、缆车）；城际交通通过工具查询 |

**边界**：
- 不负责热度值的计算（属 M17），只维护基础权重
- 不负责知识图谱中的实体扩展（属 M10）

---

#### M12 模型管理

**职责**：平台所有模型的统一注册与运维（B 端）。

| 能力 | 说明 |
|------|------|
| 分类管理 | 五类固定枚举：文本对话 / 图片理解 / 向量化 / 重排序 / OCR 解析 |
| 模型注册 | 名称、类别、调用 ID、Base URL、API Key、上下文长度、超时、并发、单价 |
| 状态管理 | 启用 / 禁用；禁用后不参与任何调用 |
| 默认模型 | 每个类别设一个平台默认 |
| 删除保护 | 有知识库引用、或为当前类别默认时禁止删除 |
| 连通性测试 | 分层校验：网络连通 → 鉴权 → 接口路径 → 响应格式 → 模型可用 |
| 调用统计 | 按模型的调用次数、token 用量、延迟、失败率、成本估算 |
| 告警 | 失败率超阈值、延迟突增时通知管理员 |

**边界**：
- 不负责额度判定（属 M13）
- 不负责「用哪个模型」的运行时决策：平台默认由本模块定，知识库级覆盖由 M09 定，会话级切换由 M06 定

---

#### M13 额度服务

**职责**：用户级模型调用额度的计量与判定。

| 能力 | 说明 |
|------|------|
| 计量维度 | 调用次数 + token 用量双限，任一超限即拒绝 |
| 约束对象 | 仅约束用户，平台与模型不设总量上限 |
| 重置周期 | 自然日，每日 00:00 清零 |
| 超限行为 | 直接报错并提示重置时间 |
| 额度配置 | B 端配置默认值（默认 100 次 / 10 万 token） |
| 额度查询 | 供 M01、M03 展示剩余额度 |
| 扩展预留 | 单用户额度覆盖、按等级差异化 |

**边界**：
- 不负责模型可用性判断（属 M12）
- 不负责统计报表（属 M16，M13 只做实时判定）

---

#### M14 用户运营

**职责**：B 端对 C 端用户的管理。

| 能力 | 说明 |
|------|------|
| 用户列表 | 注册时间、登录方式、活跃度 |
| 用户详情 | 基础信息、旅游计划列表、足迹记录、对话摘要 |
| 用户分群 | 活跃 / 沉默 / 高价值 |
| 状态管理 | 封禁、解封 |

---

#### M15 系统管理

**职责**：平台级配置与治理。

| 能力 | 说明 |
|------|------|
| 系统用户 | B 端管理员账号管理 |
| 角色权限 | 角色定义、权限分配（内容运营 / 用户运营 / 数据分析） |
| 操作日志 | 记录管理员操作，支持审计 |
| 站点配置 | 网站名称、描述、注册开关、内容审核开关、数据备份 |

**边界**：
- 模型相关配置跳转至 M12
- 额度默认值跳转至 M13
- 管理员**管理操作**的权限校验由本模块提供，业务模块调用

---

#### M16 数据看板

**职责**：运营数据的统计与呈现。

| 能力 | 说明 |
|------|------|
| 用户指标 | 注册数、DAU/MAU、新增趋势 |

## 四、核心业务流程

### 4.1 流程一：智能对话主导旅行程规划

这是系统最核心、最复杂的流程。

```
【C 端】用户进入对话 → M03
  ↓
用户输入："帮我规划北京 3 日游，预算 3000"
  ↓
【M06】意图识别：行程规划（置信度 98%）
  ↓
【M06】路由至行程规划状态机
  ↓
┌─ 节点1：信息收集 ────────────────────────────────┐
│ M06 检查必要信息：目的地 ✓ / 天数 ✓ / 预算 ✓        │
│ 可选信息缺失（出发日期、兴趣）→ 追问一次            │
│ 用户不答 → 降级读取 M07 长期记忆 → 仍无则用默认值    │
└──────────────────────────────────────────────┘
  ↓
┌─ 节点2：检索候选景点 ────────────────────────────┐
│ M06 发起检索 → M08 调度                          │
│ M08 并行调用：M11 数据库 + M09 RAG                │
│ M08 融合去重 → 返回候选列表                       │
└──────────────────────────────────────────────┘
  ↓
┌─ 节点3：生成方案 ───────────────────────────────┐
│ M04 生成标准方案（匹配预算）                       │
│ M06 触发 ReAct 优化循环（最多 10 次）              │
│   每轮：Think → 调工具 → Observe → 判断是否足够     │
│   优化维度由语义决定（预算精度/路线合理性/知识增强）  │
│ M04 基于标准方案派生经济型 + 舒适型                 │
│ 全流程受 M13 额度约束、调用 M12 模型               │
└──────────────────────────────────────────────┘
  ↓
┌─ 节点4：展示方案 ───────────────────────────────┐
│ M03 渲染卡片式对比（预算→景点质量→住宿→交通→餐饮）  │
│ 用户点击查看详情 → 展示逐日行程、预算明细、文化背景   │
└──────────────────────────────────────────────┘
  ↓
┌─ 节点5~6：方案调整 ─────────────────────────────┐
│ 用户提出调整 → M06 识别调整意图                   │
│ M04 校验约束（时间/预算/逻辑冲突）→ 提示建议        │
│ 用户确认 → 询问「保存为新方案 / 覆盖原方案」        │
└──────────────────────────────────────────────┘
  ↓
【M04】保存为行程（状态：规划中）
  ↓
【M07】更新偏好记忆（目的地、预算水平、兴趣）
  ↓
【M17】埋点记录（生成计划行为）
```

**涉及模块**：M03、M06、M04、M08、M09、M11、M12、M13、M07、M17

### 4.2 流程二：景点咨询（Plan + ReAct）

```
【M03】用户："故宫值得去吗？"
  ↓
【M06】意图识别：景点咨询（置信度 95%）
  ↓
【M06】Plan 阶段：制定步骤
  1. 查数据库基础信息
  2. 不够则 RAG 查评价
  3. 还不够则 GraphRAG 查文化价值
  4. 整合生成回答
  ↓
【M06】ReAct 循环
  循环1：M06 → M08 → M11 查询数据库
        Observe：门票 60 元、开放时间
        Think：缺少评价性内容，继续
  循环2：M06 → M08 → M09 RAG 检索
        Observe：评价内容
        Think：信息足够，结束
  ↓
【M06】整合信息 → 调用 M12 模型生成回答
  ↓
【M03】流式渲染回答 + 引用来源可展开
  ↓
【M13】计量本次调用的次数与 token
```

**关键点**：M06 最多循环 10 次；每次工具调用失败时按「重试 3 次 → 降级」处理；RAG 为空时 M08 用通用知识兜底。

### 4.3 流程三：知识库文档入库

```
【B 端】管理员在 M09 创建知识库
  ↓
管理员进入「配置」→ 设置切分参数、分隔符、向量化模型、重排序模型
  ↓
【M12】校验所选向量化模型是否启用、是否为默认
  ↓
管理员上传文件（可批量）
  ↓
【M09】文件入队 → 状态：排队中
  ↓
┌─ 归一化链路 ────────────────────────────────┐
│ 格式路由：按扩展名选解析器                    │
│   PDF/图片 → MinerU → Markdown + 坐标        │
│   Word     → 转 Markdown                     │
│   Excel    → 结构化 JSON（MD 仅展示）         │
│   TXT/MD   → 直读                            │
│   网页     → 抓取转 Markdown                  │
│ 状态：解析中（按已解析页数 / 总页数计进度）     │
└────────────────────────────────────────────┘
  ↓
清洗去噪 → 状态：切分中
  ↓
结构感知切分（按标题层级 + 分隔符优先级）
  ↓
【M12】调用向量化模型 → 状态：向量化中
  ↓
写入向量库 → 状态：完成（记录入库切分参数）
  ↓
管理员可预览：原始文档 / Markdown / 切片
```

**配置变更分支**：
- 改**切分参数** → 仅影响后续新文件，已入库文档标注「旧参数 ⚠️」
- 改**向量化模型** → 弹窗确认 → 标记「待重建」→ **暂停检索** → 管理员手动触发重建

### 4.4 流程四：行程状态流转与足迹生成

```
【M04】计划创建 → 状态：规划中（完全可编辑、可删除）
  ↓ 用户点击「确认计划」
状态：待进行（可编辑、可取消回规划中）
  ↓ 到达出发日期（定时任务自动触发）
状态：进行中（可微调，不可取消）
  ↓ 结束日期后自动提醒
【M03/M01】用户收到提醒 → 手动确认「已完成」
  ↓
状态：已完成（不可修改行程内容，可补充 UGC）
  ↓
【M05】自动生成足迹（按行程中的景点）
  ↓
【M05】用户补充：照片、游记、评分
  ↓
【M07】偏好记忆更新（实际去过的地方、评分高的类型）
  ↓
【M17】埋点记录（完成计划、足迹生成）
```

### 4.5 流程五：模型不可用与额度超限

```
【M06】用户发起对话
  ↓
【M13】校验额度：次数 + token 是否超限
  ├─ 超限 → 返回错误「今日额度已用尽，明日 00:00 重置」
  │          用户无法继续，流程终止
  └─ 未超限 → 继续
  ↓
【M06】选取模型：会话级选择 > 知识库级配置 > 平台默认（M12）
  ↓
【M12】发起调用
  ├─ 成功 → 返回结果 → M13 计量本次消耗
  └─ 失败 → 明确返回错误原因（超时/鉴权/限流/服务端异常）
             ↓
           【M03】提示「模型 A 暂不可用（原因），可切换到：B / C」
             ↓
           用户手动选择其他模型 → 重新发起
```

**设计要点**：不自动降级，模型切换权交给用户，仅在当前会话内生效。

```
【M17】埋点记录（图谱浏览、节点点击）
```

## 六、模块边界的关键约束

以下是梳理过程中识别出的、必须在设计阶段遵守的约束：

| 编号 | 约束 | 来源 | 违反后果 |

| C1 | 一个知识库对应一个向量空间，切分参数与向量模型必须知识库级唯一 | 需求 2.2.4.2 | 同库向量混存，检索静默失效 |

## 七、已确认的决策（第一轮）

以下问题已于评审中确认，并已同步至需求文档。

### 7.1 文档与原型不一致的处理

| 编号 | 问题 | 决策 |
|------|------|------|
| Q12 | 发现页 | **以原型为准**，保留三个板块（热门知识图谱 / 用户游记 / 活动推荐），已补入需求 2.1.8 |
| G2 | 额度查看入口 | **仅个人中心**，作为独立区块；对话界面不重复展示 |

### 7.2 核心业务规则

| 编号 | 问题 | 决策 |
|------|------|------|
| Q1 | RAG 检索参数 | **平台给默认值，知识库可覆盖**<br>默认 top-k = 5（可选 3/5/10）<br>默认相似度阈值 = 0.5 |
| Q2 | 检索结果融合 | **按相关性统一排序**<br>排序依据：交给重排序模型统一打分（不用各源原始分数）<br>平局处理：按来源权威性（官方数据 > 知识库 > 通用知识） |
| Q3 | 知识库删除 | **二次确认后立即硬删除**，不可恢复<br>**有任意文件处于处理中（排队/解析/切分/向量化）时禁止删除** |
| Q4 | GraphRAG 兜底 | **① 先转 RAG 检索该实体** → **② RAG 仍无结果则用模型通用知识回答并标注**「以下内容来自通用知识，非平台收录」 |
| Q5 | 额度覆盖范围 | **C 端对话计入，B 端文档处理不计入**<br>B 端处理的调用记录仅计入模型调用统计 |

**决策对模块划分的影响**：

| 决策 | 影响 |
|------|------|
| Q1 | M09 知识库配置新增「检索参数」区块（top-k、阈值） |
| Q2 | M08 需依赖重排序模型；M12 的重排序模型成为检索链路的必需组件（非可选） |
| Q3 | M09 删除逻辑需校验文档处理状态；M12 的引用保护需与 M09 状态联动 |
| Q4 | M08 兜底链路由两级扩展为三级（RAG → 通用知识） |
| Q5 | M13 额度计量需区分调用来源；M12 统计需支持「系统调用」与「用户调用」分类 |

### 7.3 中优先级业务规则

| 编号 | 问题 | 决策 |
|------|------|------|
| Q6 | 文档失败重试 | **不限重试次数**；**所有失败类型均可重试**，不做可恢复/不可恢复区分 |
| G5 | 模型调用重试 | **自动重试最多 2 次**，仍失败则报错并提示用户手动切换模型（不自动降级） |
| Q7/G3 | 方案候选集生命周期 | **未选中方案保留**，挂在行程下作为「备选方案」，用户可随时切回 |
| Q8 | 多会话并发编辑 | **编辑锁定**：同一行程同一时间仅一个会话可编辑，其他会话只读 |
| Q13-补 | 已完成行程的 UGC 边界 | UGC 指足迹中的照片/游记/评分，**在足迹模块补充**；行程本身完全锁定 |

### 9.2 核心设计判断

1. **Agent 与对话前台分离**：M03 只管收发与呈现，M06 负责所有决策。这样对话 UI 迭代不影响 AI 逻辑。

2. **记忆独立成模块**：需求中记忆被三方使用（Agent 上下文、推荐依据、个人中心展示），内嵌于 Agent 会造成跨模块隐性依赖。

3. **检索调度独立**：M08 只做「选什么源、怎么合、如何兜底」，具体检索能力归各数据模块。这样知识库调 top-k 不需改 Agent。

4. **额度独立于模型管理**：模型管理管「模型能不能用」，额度管「这个用户还能不能用」，职责正交。

5. **知识库与知识图谱并列**：两者都是知识资产但性质不同——知识库是「文档的语义检索」，图谱是「实体的关系推理」，不应合并。
