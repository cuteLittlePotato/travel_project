# 本地混合开发环境

## 为什么用混合模式

改一行代码就上传服务器重建镜像，一轮至少 2~5 分钟（弱网下更久）。
把业务服务放在本机、中间件继续用测试服务器上已部署的实例，
改代码即时生效，一轮验证降到秒级。

| 组件 | 运行位置 | 原因 |
|---|---|---|
| FastAPI（API） | **本机** | 高频修改，需要热重载 |
| Celery worker / beat | **本机** | 任务逻辑需要调试 |
| Next.js（C 端） | **本机** | 前端热更新 |
| Vite（B 端） | **本机** | 前端热更新 |
| PostgreSQL | 192.168.75.100 | 有数据、有扩展，本地装一份成本高 |
| Redis | 192.168.75.100 | 同上 |
| Milvus / Neo4j / ES / MinIO | 192.168.75.100 | 镜像大、资源占用高 |
| RabbitMQ | 192.168.75.100 | 同上 |
| LiteLLM / Langfuse | 192.168.75.100 | 已配好模型与凭证 |

## 前提条件

1. 本机能访问 `192.168.75.100` 的以下端口：

   | 端口 | 服务 |
   |---|---|
   | 15432 | PostgreSQL |
   | 16379 | Redis |
   | 17687 | Neo4j Bolt |
   | 19530 | Milvus |
   | 19200 | Elasticsearch |
   | 19000 | MinIO |
   | 5672 | RabbitMQ |
   | 14000 | LiteLLM |
   | 13000 | Langfuse |

   跑 `python scripts/dev/check_remote_services.py` 一次性确认。

2. 本机已安装：Python 3.12、[uv](https://docs.astral.sh/uv/)、Node.js 18+。
   不需要安装 Docker。

## 首次配置

```bash
# 1. 安装依赖
uv sync

# 2. 生成 backend/.env（自动从服务器读取服务凭据，不会打印到终端）
python scripts/dev/setup_local_env.py

# 3. 检查连通性
python scripts/dev/check_remote_services.py

# 4. 前端依赖
cd frontend/c-end && npm install
cd frontend/b-end && npm install
```

## 日常开发

开多个终端分别启动需要的服务：

```bash
# Windows PowerShell
.\scripts\dev\dev.ps1 api        # http://localhost:8000/docs
.\scripts\dev\dev.ps1 c-end      # http://localhost:3000
.\scripts\dev\dev.ps1 b-end      # http://localhost:5173/admin/
.\scripts\dev\dev.ps1 worker     # 需要调试异步任务时
.\scripts\dev\dev.ps1 beat       # 需要调试定时任务时
```

```bash
# Git Bash / WSL / macOS / Linux
./scripts/dev/dev.sh api
./scripts/dev/dev.sh c-end
```

## 数据使用

**不做数据隔离。** 测试服务器就是开发测试用的，本地调试直接读写同一个 `travel` 库：

- 调试产生的数据保留在测试库，不需要清理
- 需要重置时直接跑 `scripts/sql/schema.sql` 重建
- 不需要在本地另起 PostgreSQL 实例

## 何时仍需上服务器

混合模式解决的是「开发调试慢」，以下场景仍要走完整构建：

- 验证 Docker 镜像（Dockerfile 改动）
- 验证 Nginx 路由（`/admin/`、SSE 转发）
- 验证容器间网络与服务发现
- 上线前的整体验收

这些属于 M0-T14「部署编排补齐与本地联调环境验证」的范围，不占日常开发时间。

## 与服务器部署的关系

本地开发的代码与服务器部署的代码是**同一份源码**。区别只在：

| 项 | 本地 | 服务器 |
|---|---|---|
| 进程管理 | `uvicorn --reload` | Docker + restart 策略 |
| 中间件地址 | `192.168.75.100:xxxxx` | `travel-postgres:5432` 等容器名 |
| 配置来源 | `backend/.env` | `/opt/travel/deploy/.env.app` |
| 前端 API 代理 | Next.js rewrites / Vite proxy | Nginx |

因此本地验证通过的代码，部署时只需换一份环境变量。
