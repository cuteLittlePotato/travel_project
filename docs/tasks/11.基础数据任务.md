#### [M11-T01] 基础数据表迁移与 ORM

- 所属模块：M11 基础数据
- 优先级：P0
- 依赖：M0-T13
- 关联文档：数据库设计 §3.2（region / attraction / attraction_category / attraction_category_relation / restaurant / hotel / transport / popularity_stat / activity）
- 任务类型：DB迁移

- 任务描述：为九张表编写迁移与 ORM 模型。

- 交付物：
  - [ ] 迁移脚本
  - [ ] `backend/app/modules/catalog/models.py`

- 验收标准（DoD）：
  - [ ] `attraction_category.category_type` CHECK 含 `theme/level`
  - [ ] `attraction_category_relation` 唯一约束 `(attraction_id, category_id)`（评审 §Q4）
  - [ ] `attraction` 唯一约束 `(name, city_id)`
  - [ ] `activity` 的 `chk_activity_date` 约束存在（`end_date >= start_date`）
  - [ ] 规范检查：无物理外键；坐标 `NUMERIC(10,7)`；金额 `NUMERIC`

- 边界与异常：`region.level` 限制 1-2；`region.code` 唯一（国标 GB/T 2260，评审 §Q8）。

- 预估工时：1.5h

#### [M11-T10] 热度计算数据管道与定时任务

- 所属模块：M11 基础数据
- 优先级：P0
- 依赖：M11-T01, M02-T13, M17-T02
- 关联文档：数据库设计 §3.2（popularity_stat）、需求 §3.2（热度计算流程）
- 任务类型：后端

- 任务描述：实现热度计算的**数据管道**：读取 `user_event` 聚合行为计数 → 调用 `M17-T02` 的纯算法 → 写入 `popularity_stat` → 每小时定时调度。**算法逻辑不在本任务实现**。

- 交付物：
  - [ ] `backend/app/tasks/schedule/popularity.py` — 每小时执行
  - [ ] `backend/app/modules/recommend/popularity_service.py`

- 验收标准（DoD）：
  - [ ] 管道正确读取 `user_event` 聚合并调用 M17-T02 算法（单测，Mock 算法返回值）
  - [ ] 定时任务幂等，重复执行结果一致（单测）
  - [ ] 规范检查：只更新 `popularity_stat`，不改 `attraction.base_popularity`（运营配置值）
  - [ ] 规范检查：算法公式不在本任务重复实现（`grep -E '0\.6|0\.4' popularity_service.py` 无硬编码权重）

- 边界与异常：无行为数据的景点使用基础权重；任务执行超时需分批处理。

- 预估工时：2h
- 状态：TODO
