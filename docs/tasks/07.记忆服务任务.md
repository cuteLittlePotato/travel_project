#### [M07-T02] 记忆读写服务与惰性衰减计算

- 所属模块：M07 记忆服务
- 优先级：P0
- 依赖：M07-T01
- 关联文档：数据库设计 §3.5（衰减算法：`confidence × 0.5^(天数/90)`）、评审 §Q7
- 任务类型：后端

- 任务描述：实现记忆的写入（upsert）、读取（含衰减加权排序）、更新 `last_active_at`。衰减采用惰性计算，半衰期 90 天。

- 交付物：
  - [ ] `backend/app/modules/memory/service.py`
  - [ ] `backend/app/modules/memory/decay.py` — 衰减计算

- 验收标准（DoD）：
  - [ ] 权重计算 `confidence × 0.5^(days/90)` 有单测验证（含 0/30/90/180 天的期望值）
  - [ ] 读取结果按当前权重降序（单测）
  - [ ] upsert 相同 `(user_id, memory_type, memory_key)` 时更新而非新增（单测）
  - [ ] **置信度合并 `新 = 旧 × 0.7 + 观测 × 0.3` 有单测**（旧=0.5、观测=1.0 → 0.65）（评审 §Q3）
  - [ ] 首次写入时 `confidence` 直接等于来源观测值（单测）
  - [ ] 规范检查：不存储衰减后的值，`confidence` 保持原值（DB 断言）

- 边界与异常：`last_active_at` 为空时的处理（视为 0 天）；系统时钟异常（未来时间）的防御。

- **置信度合并策略（评审 §Q3 已确认）**：
  - 公式：`confidence = 旧 × 0.7 + 新观测 × 0.3`（α=0.3，所有来源统一）
  - 新观测的 confidence 按来源分级赋值：

    | 来源 | 新观测值 |
    |---|---|
    | 用户在偏好设置显式选择 | 1.0 |
    | 用户在对话中明确表达 | 0.9 |
    | 用户创建含该类型的计划 | 0.8 |
    | 用户浏览/收藏多个同类景点 | 0.7 |
    | 用户足迹中出现该类型 | 0.6 |
    | 用户单次浏览某类型景点 | 0.3 |

  - 首次写入（无旧值）时 `confidence = 新观测值`
  - 合并后 `last_active_at` 更新为当前时间

- 预估工时：2h

#### [M07-T03] 偏好提取（从对话历史）

- 所属模块：M07 记忆服务
- 优先级：P1
- 依赖：M07-T02, M06-T01
- 关联文档：需求 §2.1.3.8（偏好学习来源）、数据库设计 §3.5（`source` 字段）
- 任务类型：后端

- 任务描述：异步分析对话历史，提取用户偏好写入长期记忆。触发时机：会话结束或计划完成后。

- 交付物：
  - [ ] `backend/app/tasks/memory/preference_extract.py` — Celery 任务
  - [ ] 提取提示词（使用 M06 的 LLM 客户端）

- 验收标准（DoD）：
  - [ ] 从含偏好的对话中提取出结构化标签（单测，Mock LLM）
  - [ ] 写入的记忆 `source='conversation'`（DB 断言）

- 边界与异常：对话过短（<3 轮）时跳过；已存在的记忆项按**置信度合并策略**处理（评审 §Q3，见 M07-T02）；对话提取的观测值 = 0.9。

- 优先级：P1

- 交付物：
  - [ ] `backend/app/modules/memory/cleanup.py`

- 验收标准（DoD）：
