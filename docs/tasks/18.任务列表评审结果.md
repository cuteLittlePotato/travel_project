## 八、待确认事项的确认结论

> 原 6 项待确认事项已于 2026-11-06 逐项与用户交互确认，结论与落地情况如下。**全部已闭环，无遗留。**

### ✅ Q1：Token 存储策略 — 已确认 B

**确认结论**：Access Token 存**内存**，Refresh Token 存 **httpOnly Cookie**。
- Cookie 属性：`httpOnly` + `Secure` + `SameSite=Lax`
- **SSR 首屏不查询登录状态**（首屏统一渲染未登录态，客户端 hydrate 后再判定），避免 SSR 依赖 Cookie 导致页面无法静态化

**落地位置**：
| 任务 | 修改内容 |
|---|---|
| M01-T16 | DoD 增加「Access Token 存内存、Refresh 存 httpOnly Cookie」「localStorage 不含任何 Token」「Refresh Cookie 属性断言」 |
| M01-T19 | 状态管理按「内存 + Cookie」实现 401 自动刷新 |
| M15-T09 | 边界说明改为「Token 存储策略与 C 端一致」 |

---

### ✅ Q2：`activity` 表内容来源 — 已确认 A

**影响**：M11-T09（活动管理接口）与 M11-T13（B 端活动管理页）的现有设计已完整覆盖，**无需新增或修改任务**。运营侧无素材时该功能为空表属预期，不视为缺陷。

### ✅ Q3：记忆置信度合并策略 — 已确认 C（加权平均）

**确认结论**：所有来源统一使用 α = 0.3 的加权平均：

```
confidence = 旧值 × 0.7 + 新观测 × 0.3
```

新观测值按来源分级：

| 来源 | 新观测值 |
|---|---|
| 用户在偏好设置显式选择 | 1.0 |
| 用户在对话中明确表达 | 0.9 |
| 用户创建含该类型的计划 | 0.8 |
| 用户浏览/收藏多个同类景点 | 0.7 |
| 用户足迹中出现该类型 | 0.6 |
| 用户单次浏览某类型景点 | 0.3 |

首次写入（无旧值）时 `confidence = 新观测值`；合并后 `last_active_at` 更新为当前时间。

**落地位置**：
| 任务 | 修改内容 |
|---|---|
| M07-T02 | 增加「置信度合并策略」章节（公式 + 来源分级表），DoD 增加合并公式单测与首写断言 |
| M07-T03 | 边界说明改为引用 Q3 策略，对话来源观测值 = 0.9 |
| M05-T08 | 边界说明改为引用 Q3 策略，足迹来源观测值 = 0.6 |

### ✅ Q4：用户分群口径 — 已确认 1-B / 2-B / 3-D + 补充 A/A
