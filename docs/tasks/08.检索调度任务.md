#### [M08-T01] 检索调度骨架与统一检索协议

- 所属模块：M08 检索调度
- 优先级：P0
- 依赖：M0-T01
- 关联文档：架构 §3.4（跨模块协作：统一检索接口）、需求 §2.1.3.7
- 任务类型：后端

- 任务描述：定义统一检索协议（请求/结果结构），实现调度骨架。**M08 不直接访问任何存储，只定义协议与编排逻辑**。

- 交付物：
  - [ ] `backend/app/modules/retrieval/protocol.py` — `RetrievalRequest`、`RetrievalResult`、`RetrievalSource`
  - [ ] `backend/app/modules/retrieval/service.py` — 调度入口 `retrieve()`
  - [ ] `backend/app/modules/retrieval/repository_protocol.py` — 各数据源需实现的接口协议

- 验收标准（DoD）：
  - [ ] 统一结果结构含 `content`/`source`/`score`/`metadata`（结构断言）
  - [ ] 数据源以协议形式注入，M08 不 import 具体数据模块（`grep -rn 'modules.knowledge_base\|modules.knowledge_graph' backend/app/modules/retrieval/` 仅允许在 adapter 层）
  - [ ] 规范检查：M08 无任何数据库/向量库/图库客户端调用（`grep -rn 'pymilvus\|neo4j\|sqlalchemy' backend/app/modules/retrieval/service.py` 无输出）

- 边界与异常：检索请求需含超时控制；单个数据源失败不影响其他源。

- 预估工时：2h

#### [M08-T05] 并行检索与结果融合

- 所属模块：M08 检索调度
- 优先级：P0
- 依赖：M08-T02, M08-T03, M08-T04
- 关联文档：需求 §2.1.3.7（并行检索、结果融合规则）、评审 §Q2
- 任务类型：后端

- 任务描述：实现多源并行检索（asyncio.gather），结果融合。**融合规则：按重排序模型统一打分排序，平局按来源权威性（官方数据 > 知识库 > 通用知识）。**

- 交付物：
  - [ ] `backend/app/modules/retrieval/fusion.py` — 融合与去重
  - [ ] 按问题类型的检索策略路由

- 验收标准（DoD）：
  - [ ] 三源并行执行，总耗时接近最慢单源而非累加（单测，Mock 延迟）
  - [ ] 相同内容去重保留最高分（单测）
  - [ ] 平局时按来源优先级排序（单测）
  - [ ] 规范检查：融合使用重排序模型打分，不使用各源原始分数直接比较（代码审查 + 单测）

- 边界与异常：单源超时不影响整体（使用 `asyncio.wait_for`）；重排序模型不可用时退化为按源优先级排序。

- 预估工时：2h
- 状态：TODO

#### [M08-T06] 降级兜底链路

- 所属模块：M08 检索调度
- 优先级：P0
- 依赖：M08-T05
- 关联文档：需求 §2.1.3.7（质量控制与兜底，三级链路）、评审 §Q4
- 任务类型：后端

- 任务描述：实现三级兜底：GraphRAG 为空 → 转 RAG；RAG 仍为空 → 标记需用通用知识；结果矛盾时按权威性选择。

- 交付物：
  - [ ] `backend/app/modules/retrieval/fallback.py`

- 验收标准（DoD）：
  - [ ] GraphRAG 空结果时自动触发 RAG 检索（单测）
  - [ ] RAG 也为空时返回 `need_general_knowledge=true` 标记（单测）
  - [ ] 矛盾结果按「官方数据 > 知识库 > 通用知识」选择（单测）
  - [ ] 规范检查：降级链路与需求 §2.1.3.7 的三级顺序一致

- 边界与异常：避免无限降级循环（最多 2 次转源）；降级过程记录日志便于分析。

- 预估工时：1.5h
- 状态：TODO
