#### [M02-T01] C 端查询所需的 ORM 与 Repository

- 所属模块：M02 景点内容
- 优先级：P0
- 依赖：M11-T01（景点/分类/地区表已建）
- 关联文档：数据库设计 §3.2（attraction / attraction_category / attraction_category_relation / region / popularity_stat / transport）
- 任务类型：后端

- 任务描述：实现 C 端只读查询所需的 Repository，含景点列表分页、按分类/城市筛选、详情聚合（含分类、交通）、热度读取。

- 交付物：
  - [ ] `backend/app/modules/attraction/repository.py`
  - [ ] `backend/app/modules/attraction/schemas.py` — C 端响应模型

- 验收标准（DoD）：
  - [ ] 列表查询仅返回 `is_published=true` 的景点（单测）
  - [ ] 分类筛选为「且」关系（多分类同时满足）（单测）
  - [ ] 热度值来自 `popularity_stat.final_popularity`，无记录时回退 `attraction.base_popularity`（单测）

- 边界与异常：分类表无数据时列表仍可正常返回；`popularity_stat` 关联缺失不导致 N+1 查询。

- 预估工时：2h

#### [M02-T06] 景点知识图谱查询接口

- 所属模块：M02 景点内容
- 优先级：P0
- 依赖：M02-T01, M10-T01
- 关联文档：API §4.3
- 任务类型：API

- 任务描述：实现 `GET /api/v1/attractions/{id}/knowledge-graph`。从 Neo4j 查询以该景点为中心的关系网络，支持 `depth`（1-2）与 `relation_types` 过滤。

- 交付物：
  - [ ] `backend/app/api/v1/c_end/knowledge_graph.py::attraction_graph`
  - [ ] `backend/app/modules/knowledge_graph/graph_repository.py` — Cypher 查询

- 验收标准（DoD）：
  - [ ] `depth=1` 返回一跳关系，`depth=2` 返回两跳（集成测试，需 Neo4j 有数据）
  - [ ] 节点数上限 50，超出时截断并返回标记（单测）
  - [ ] `has_sub_graph` 正确标识节点是否有进一步关系（单测）
  - [ ] 接口返回 200 且结构含 `center`/`nodes`/`edges`（接口测试）

- 边界与异常：Neo4j 中不存在该景点节点时返回空图谱而非 404（景点本身存在于 PG）；查询超时需返回降级提示。

- 预估工时：2h
- 状态：TODO
